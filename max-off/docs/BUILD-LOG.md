## 4 Sep 2026 · Gate 1 · the cap works at checkout

**Built** — `extensions/max-off-cap`, a discount Function scaffolded with
`shopify app generate extension --template discount --flavor typescript`.

- Target `cart.lines.discounts.generate.run` only. The delivery-options target the template
  scaffolds was deleted — V1 is whole-order scope, so a shipping target would be dead code.
- `src/cap.ts` holds the arithmetic: `parseDecimalToMinor`, `capDiscount`, `toDecimalString`,
  `formatMoney`. All integer minor units. The `Decimal` scalar arrives as a *string*
  ("1400.00"), so it is parsed straight to cents and never becomes a float.
- `src/cart_lines_discounts_generate_run.ts` returns no operations unless `ORDER` is in
  `discount.discountClasses`, reads `cart.cost.subtotalAmount`, and emits `orderDiscountsAdd`
  with `value: {fixedAmount: {amount}}` against an `orderSubtotal` target,
  `selectionStrategy: FIRST`.
- Cap hard-coded at 15% / 150.00 (`PERCENTAGE`, `CAP_MINOR`). Gate 2 moves these to the
  metafield.
- Buyer-facing message: `15% off (max 150.00 USD)`. The currency comes from
  `cart.cost.subtotalAmount.currencyCode`.

**Verified**

- `npm run lint` — passes.
- `npm test` — 36 passing. 30 unit tests in `tests/cap.test.ts` cover all eight rows of spec

### Spec corrections found while verifying against the real schema

1. **§3.2 is wrong about `FixedAmount`.** It says the union member has `amount, currencyCode`. In
   the 2026-10 schema `input FixedAmount` has **only** `amount: Decimal!` — "The fixed amount
   value of the discount, in the currency of the cart." There is nowhere to put a currency code,
   which is consistent with the "amounts relabel, they never convert" rule.
2. **The Function cannot see the discount code.** `type Discount` in the Function schema exposes
   exactly two things: `discountClasses` and `metafield(namespace:, key:)`. No title, no code. So
   §4.3 item 7's message `"SUMMER15 — 15% off (max 150.00 USD)"` is only reachable if the code is
   written into the cap-config metafield when the discount is created. Gate 2/3 must store it
   there. Gate 1's message drops the code prefix.
3. **`discountCodeAppCreate` requires `write_discounts`** (confirmed), and
   `DiscountCodeAppInput` has a `discountClasses: [DiscountClass!]` field — creating our discount
   must pass `[ORDER]` or the Function returns no operations. The docs disagree with themselves on
   whether `functionId` is deprecated in favour of `functionHandle` in 2026-10; resolve that in
   Gate 3 against the live schema, not the docs.

### Open for Sophea — Gate 1 cannot close without this

The Function is built and tested, but there is no way yet for a discount that *uses* it to exist
on the dev store, and both routes need a decision:

- **Route A — create it in the Shopify admin.** This is what spec §7 assumes ("create a discount by
  hand in the Shopify admin"). It likely needs `[extensions.ui]` + `[extensions.ui.paths]` in
  `shopify.extension.toml` pointing at a create route in our app — i.e. Gate 3's create form,
  pulled forward. The docs do not state whether Shopify shows a default form without those paths,
  and this session would not guess.
- **Route B — create it once with `discountCodeAppCreate`** from GraphiQL, running as our app.
  Keeps Gate 1 tiny, but needs `write_discounts` in `access_scopes`, which currently holds only the
  template's demo scopes. Changing `access_scopes` needs Sophea's sign-off (CLAUDE.md rule 9).
